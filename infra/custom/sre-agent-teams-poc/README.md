# SRE Agent Teams POC （シナリオ概要）

## 概要

このシナリオは、**SRE エージェント**と **Microsoft Teams** の統合における概念実証（PoC）です。

Teams チャネル経由で SRE Agent を呼び出し、Azure リソースの管理タスク（問題調査、修復提案、ステータス確認など）をエージェント駆動で自動化します。

**シナリオ分類**: `adhoc` （単発・再利用非予定）

---

## リソース構成

### インフラストラクチャ

| リソース | 役割 |
|---------|------|
| **Managed Identity (User-Assigned)** | Azure リソース認証（RBAC ロール割り当て対象） |
| **Log Analytics Workspace** | ログ集約・分析 |
| **Application Insights** | アプリケーション可視化・トレース |
| **Storage Account** | Teams <→ SRE Agent 間の会話スレッドマップ（Table Storage） |
| **Container Registry** | Teams ボット アプリケーション イメージ管理 |
| **Container Apps Environment** | Teams ボット デプロイメント基盤（Consumption 課金） |
| **Container App** | Teams ボット インスタンス（FQDN 公開） |
| **SRE Agent** | Azure 管理エージェント（eastus2 リージョン） |
| **Bot Service** | Teams チャネル統合 |

---

## デプロイ方法

### 前提条件

- Azure CLI がインストール済み
- 適切な Azure サブスクリプション権限
- Container Image がレジストリに存在 (`sre-teams-bot:aca-v7`)

### デプロイ実行

```powershell
cd infra/custom/sre-agent-teams-poc
.\deploy-new-env.ps1 -ScenarioCode <your-code>
```

パラメータの詳細は `bicep/main.bicepparam` を参照してください。

## リポジトリ方針との整合性

このシナリオは、リポジトリの設計方針に**段階的に適合化**されています。

### 現在の状態

✅ **完了**:
- すべての API バージョンを最新 GA版に統一（2026-06-21）
- パラメータ説明を日本語で統一

⏳ **計画中**:
- Azure Verified Modules（AVM）への置換（段階的導入）
- パラメータ構造の最小化（リポジトリ方針に準拠）

### AVM 化の段階的計画

このシナリオでは、将来的に以下の順序で AVM 化を推進します。リポジトリの `module-refactor-policy.md` に準拠します。

#### フェーズ 1: パイロット（低リスク）

置換容易なリソース から開始：

| リソース | AVM モジュール | 期待される効果 | リスク |
|---------|--------------|----------|-------|
| Managed Identity | `microsoft/avm-res-managedidentity-userassignedidentity` | RBAC 割り当てロジック統一 | 低 |
| Log Analytics | `microsoft/avm-res-operationalinsights-workspace` | ログ保持ポリシー統一 | 低 |
| Application Insights | `microsoft/avm-res-insights-component` | トレース設定統一 | 低 |

#### フェーズ 2: 中程度複雑度

依存関係が限定的：

| リソース | AVM モジュール | 注意点 |
|---------|--------------|-------|
| Container Registry | `microsoft/avm-res-containerregistry-registry` | RBAC 参照の確認 |
| Storage Account | `microsoft/avm-res-storage-storageaccount` | Table Service スコープ確認 |

#### フェーズ 3: 高複雑度（要検討）

複数の相互参照とパラメータ連携が必要：

| リソース | 状況 |
|---------|------|
| **Container Apps Environment** | Log Analytics 統合、workload profiles の AVM サポート確認 |
| **Container App** | env 変数の管理 ID 参照が多く、AVM 柔軟性を検証必要 |
| **Bot Service** | Container App との FQDN 連携が必須 |
| **SRE Agent** | 新規リソース、AVM 対応状況不明 → 中期的に監視 |

### AVM 化実装時の手順

1. パイロット リソースで `microsoft/avm-*` を参照する Bicep へ切り替え
2. テスト実行 → 既存出力値が変わらないことを確認
3. 他シナリオの類似リソースも置換（DRY 原則）
4. GitHub Issue で追跡

## ビジネス理由による設定

以下の設定はビジネス要件のため、既定値として固定：

| パラメータ | 既定値 | 理由 |
|----------|-------|------|
| `location` | `koreacentral` | アプリケーション リソースのリージョン（ビジネス要件） |
| `agentLocation` | `eastus2` | SRE Agent リージョン（利用可能な最良リージョン） |

これらはリポジトリ方針の例外です。
